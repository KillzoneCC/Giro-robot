# AGENTS.md

Ориентировка для AI-агентов (и новых разработчиков), работающих с этим
репозиторием.

## Что это за проект

**Giro-Robot** — балансирующий двухколёсный робот (перевёрнутый маятник) на
Arduino Nano + MPU6050 + 2 шаговых мотора (TMC2208). Прошивка на C++ (Arduino
framework). В корне также лежит Python-инструмент `pid_tuner/` для офлайн-симуляции
и подбора коэффициентов.

Стабилизация — **каскадный PID**:

- **Speed PID** (`SpeedController`, внешний контур): целевая скорость м/с и текущая
  оценка → дополнительный угол наклона.
- **Angle PID** (`Stabilizer`, внутренний контур): целевой угол (нуль + вклад
  Speed PID) → команда на моторы (шаг/с).

## Ключевые файлы прошивки

| Файл | Роль |
|---|---|
| `Giro_robot.ino` | Главный цикл, Serial-команды, диспетчер safety, каскад |
| `config.h` | Пины, пороги, коэффициенты по умолчанию |

## Сборка и запуск

1. Arduino IDE → открыть `code/Giro_robot/Giro_robot/Giro_robot.ino`.
2. Плата: **Arduino Nano** (ATmega328P, `Old Bootloader` — если требуется).
3. Библиотеки: **Adafruit MPU6050**, **Adafruit Unified Sensor**.
4. Залить. Открыть Serial Monitor, 115200 бод.
5. Если EEPROM пуст → `c` для калибровки. Иначе робот готов сразу.
6. `V,0,0` — баланс на месте.

## Правила правок

- **Не менять имена Serial-команд** и ключи EEPROM без миграции — есть
  сохранённые конфигурации в `c:` и у пользователя.
- **Пороги и коэффициенты** — только в `config.h`, с комментарием.
- **Весь сброс контуров** — только через `resetAllControlState()` в
  `Giro_robot.ino`. Никакого рассыпанного `static` в `loop()` для состояния
  аварии/накоплений PID.
- **Авария** имеет ровно одно состояние `fallen` (см. `safety.h`). Не возвращать
  отдельную lift-логику — даёт ложные срабатывания на манёврах.
- **PID::reset()** должен очищать и телеметрию (`_lastP/I/D`, `_lastErrorOut`) —
  инвариант.
- **Документация** — любое изменение поведения правила/порога отражать в
  соответствующем `doc/*.md`. В корне держим только `AGENTS.md` и `README.md`.

## Проверочные сценарии

- Робот упал → через `FALL_DEBOUNCE_MS` (200 мс) `STATUS fall=1`, моторы
  остановлены, интегралы PID обнулены.
- Робота поставили вертикально → через `RECOVERY_DEBOUNCE_MS` (400 мс) при
  малой угловой скорости `fall=0`, моторы включены, каскад стартует с нуля.
  Перезагрузка не нужна.
- Резкий разгон с углом ошибки 10–20° → `fall` остаётся 0, работает
  `SOFT_ERR_*`-смягчение.
