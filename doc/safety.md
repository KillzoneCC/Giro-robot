# Безопасность: падение и восстановление

## Модель аварии

В прошивке есть единственное аварийное состояние — **`fallen`**. Оно означает
**реальное падение**: робот физически лежит на корпусе, колёса не могут его
вернуть в вертикаль. Физического авто-подъёма нет — робот должен быть поставлен на
колёса пользователем.

Отдельной детекции «подняли рукой» (lift) больше нет — она давала ложные
срабатывания на обычных манёврах. Текущая логика устойчива к кратковременным
перегрузам по углу при разгонах/торможениях.

## Состояния и переходы

```
    NORMAL ──(|angle-target| > FALL_ANGLE_DEG, >= FALL_DEBOUNCE_MS)──▶ FALLEN
    FALLEN ──(|angle-target| < FALL_RECOVERY_DEG
              И |gyroRate| < FALL_RECOVERY_RATE_MAX,
              >= RECOVERY_DEBOUNCE_MS)──▶ NORMAL
```

События, которые прошивка возвращает из `FallHandler::update()`:

| Событие | Когда | Что делает прошивка |
|---|---|---|
| `FALL_JUST_FELL` | Порог `FALL_ANGLE_DEG` выдержан `FALL_DEBOUNCE_MS` | `motors.stop()`, `motors.disable()`, `resetAllControlState()` |
| `FALL_JUST_RECOVERED` | Порог `FALL_RECOVERY_DEG` и `FALL_RECOVERY_RATE_MAX` выдержаны `RECOVERY_DEBOUNCE_MS` | `resetAllControlState()`, `motors.enable()` |
| `FALL_NO_CHANGE` | Нет перехода | Если `isFallen()` — моторы остаются остановлены |

Таймеры инкапсулированы в `FallHandler` и сбрасываются немедленно, как только
условие нарушено. Никакие `static` переменные в `loop()` для безопасности не
используются.

## Пороги (config.h)

| Константа | Значение | Смысл |
|---|---|---|
| `FALL_ANGLE_DEG` | 55.0f | Достижение этого угла — кандидат в падение |
| `FALL_DEBOUNCE_MS` | 200 | Подтверждение падения |
| `FALL_RECOVERY_DEG` | 15.0f | Возврат к цели (в пределах этого) |
| `FALL_RECOVERY_RATE_MAX` | 60.0f | Макс. угловая скорость, °/с (робот должен стоять спокойно) |
| `RECOVERY_DEBOUNCE_MS` | 400 | Подтверждение восстановления |

Критерий «робот спокоен» (`|gyroRate| < FALL_RECOVERY_RATE_MAX`) защищает от
ложного восстановления в момент размашистого прохода через вертикаль (когда
робот падает через зону `FALL_RECOVERY_DEG` насквозь).

## Полный сброс накоплений

На каждом событии (`JUST_FELL`, `JUST_RECOVERED`) вызывается
`resetAllControlState()`:

- `stabilizer.reset()` — Angle PID: `_integral`, `_lastError`, `_lastP/I/D`,
  `_lastErrorOut`, `_motorSpeed`.
- `speedController.reset()` — Speed PID + **`smoothOffset`** + **`prevTargetSign`**
  (поля Speed PID: после рефакторинга они живут внутри `SpeedController`,
  не в `.ino`).
- `velocityFusion.setVelocity(0)` — обнуление `_v` и `_vAccel`.
- `twist.stop()` — сброс целевой скорости и ramp.

`orientation` при падении не сбрасываем: фильтр продолжает интегрировать гироскоп (на полу оценка pitch может быть неточной). Если после восстановления робот «ведёт» или кажется смещённым по вертикали, выполните команду **`z`** (нуль по текущему вертикальному положению, см. [calibration.md](calibration.md)).

В течение окна **recovery settle** (`RECOVERY_SETTLE_MS`, см. `config.h`) не вызывается
`velocityFusion.update()` — фузия скорости заморожена (`setVelocity(0)`, для контуров подаётся `v_fused = 0`), чтобы толчки при подъёме не накапливали ложную скорость в интеграторе акселерометра (иначе внешний Speed PID мог давать устойчивый наклон «вперёд»). Ранний выход из окна — по $|v_{\mathrm{колёс}}|$ (порог `RECOVERY_SETTLE_MAX_VFUSED`) и гироскопу.

## Отладка

- Статус: `?` → `STATUS fall=0/1 hz=NN`.
- Текстовый режим: `D` — при аварии в строке появляется ` FALL`.
- Serial Plotter `G` — после восстановления видно, что `error`, `P`, `I`, `D`
  стартуют с нуля (был ли выполнен сброс).

## Типовые сценарии

**Упал и лежит** → через 200 мс `fall=1`, моторы stop+disable, PID сброшены,
цель скорости = 0. Робот ждёт внешнего вмешательства.

**Поставили вертикально после падения** → через ~400 мс устойчивого состояния
`fall=0`, `motors.enable()`, каскад стартует с чистых PID. Никакой перезагрузки
не требуется.

Дополнительно после подтверждённого восстановления действует **окно успокоения**
(см. `RECOVERY_SETTLE_*` в `config.h`): ограниченное время (или досрочно при малой |оценке скорости|
и малой |угловой скорости|) выход внешнего контура (Speed PID) не меняет целевой угол — только
балансировка Angle PID по `targetOffset`. Это уменьшает «уезд» из-за ложной скорости сразу после
постановки.

**Резкий разгон, ошибка угла 10–20°** → не падение (порог 55°). Смягчение
выхода `SOFT_ERR_*` уменьшает дёрганье моторов без активации аварии.

**Прошли через вертикаль при падении** → не ложное восстановление, потому что
`gyroRate` высокий; таймер `_recoverStartMs` сбрасывается каждый такт.
