# Host-driven автотюн PID

Порядок настройки каскада: сначала **Angle PID** в режиме `a,2` (внешний контур не даёт вклада в целевой угол), затем при необходимости **Speed PID** в режиме `a,1` при нулевой цели скорости.

Приложение **pid_tuner** (`pid_tuner/pid_tuner.py`): блок «Автотюн (ПК)» выполняет пошаговое увеличение `Kp` с интервалом «сек/шаг», опираясь на телеметрию `TLM,...` (включается командой `x,1` на МК). При падении шаг приостанавливается; после подъёма и восстановления (`STATUS fall=0`) используйте «Продолжить после падения» — отправляются `r`, затем снова режим `a,<n>` и `x,1`.

## Критерии приёмки (минимальные пороги)

Параметры по умолчанию заданы в [config.h](../code/Giro_robot/Giro_robot/config.h) (окно после recovery).

| Проверка | Порог | Примечание |
|---|---|---|
| Оценка скорости после постановки | `\|v_fused\| ≤ 0.08` м/с (или дольше стабильности) | Досрочный выход из окна `recovery settle` |
| Угловая скорость после постановки | `\|ω_pitch\| ≤ 45` °/с | Досрочный выход из окна |
| Максимум окна успокоения | `350` мс (`RECOVERY_SETTLE_MS`) | Если условия выше не выполнились раньше |

Ручной сценарий **P0**: упасть → дождаться `fall=1` → поставить робота → убедиться, что в течение ~1 с после `fall=0` нет устойчивого «уезда»; смотреть поля `aOff`, `v`, `tgt` в `TLM,...`.

Сценарий **fall → пауза автотюна**: при работе sweep перевести робота в падение → телеметрия даст `TLM_FALL` при `x,1`, статус `STATUS fall=1`. После восстановления нажать «Продолжить после падения».

## Откат по осцилляциям (ПК)

В приложении считаются пересечения нуля **ошибки угла** (`angE` в строке `TLM,...`). Если за интервал шага число пересечений превышает «max×», коэффициент возвращается к последнему успешному значению шага (упрощённая эвристика).

Сохранение в EEPROM выполняется только по команде пользователя (`w` / `w2`), не автоматически.
