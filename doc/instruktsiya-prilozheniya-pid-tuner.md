# Инструкция по приложению PID Tuner (Giro-Robot)

**Версия документа:** 2026-04  
**Файл приложения:** `pid_tuner/pid_tuner.py` (Python 3, поряд зависимостей — `pid_tuner/requirements.txt`)

Эта инструкция дополняет обобщённый [README](../README.md) и технические разделы [commands.md](commands.md), [autotune.md](autotune.md). Её удобно держать под рукой при настройке робота с ПК.

---

## 1. Для чего нужно приложение

**PID Tuner** — настольная программа для:

- подключения к Arduino по USB (Serial **115200** бод);
- правки **Angle PID** и **Speed PID** (ползунки и поля), отправки на робот и сохранения в EEPROM;
- пошагового **автоподбора Kp** (host-driven автотюн) с паузой при падении;
- просмотра **машинной телеметрии** `TLM,...` и **графиков** ошибок и составляющих P/I/D для обоих контуров.

Робот при этом работает по прошивке из `code/Giro_robot/Giro_robot/` (каскад Speed → Angle). Подробнее об архитектуре — [architecture.md](architecture.md).

## 2. Установка и запуск

1. Установите **Python 3** (на Windows при необходимости отметьте «Add to PATH»).
2. В каталоге `pid_tuner` выполните установку зависимостей:

   ```text
   pip install -r requirements.txt
   ```

   Для **вкладки «Графики PID»** нужен **matplotlib** (обычно уже в `requirements.txt`; при отсутствии: `pip install matplotlib`).

3. Запуск:

   ```text
   python pid_tuner.py
   ```

   Либо откройте `pid_tuner.py` в IDE и запустите оттуда.

4. Подключите кабель USB к Arduino, выберите **COM-порт** в приложении и нажмите **Подключить**.

Если порта нет в списке — проверьте драйвер USB–UART (CH340/FTDI и т.д.) и кабель.

## 3. Обзор вкладок

### 3.1. «PID и управление»

- **Angle PID** — внутренний контур (угол → команда моторам). Команды прошивки: `f,...`, чтение `P`, сохранение `w`.
- **Speed PID** — внешний контур (скорость → дополнительный угол). Команды: `f2,...`, `P2`, `w2`.
- Блок **целевой скорости** — задаётся как на роботе (`V,speed,turn` через интерфейс приложения). Для спокойной проверки баланса используйте **0 м/с**.
- Кнопки **«Прочитать PID»**, **«Сохранить Angle PID»**, **«Сохранить Speed PID»** — синхронизация с EEPROM по желанию.
- Дополнительные окна (график PID, IMU, скорость моторов, траектории) открываются отдельными кнопками в этом же столбце.

Рекомендация: перед автотюном убедитесь, что IMU откалиброван ([calibration.md](calibration.md)), робот стоит на поверхности и готов к тесту.

### 3.2. «Автокалибровка» (sweep Kp на ПК)

Здесь ПК по очереди подставляет **Kp** в выбранном диапазоне, держит каждый шаг заданное время (**сек/шаг**) и по телеметрии считает «качку» по ошибке (пересечения нуля). Если за шаг пересечений больше, чем **max×**, выполняется откат к последнему приемлемому Kp (см. [autotune.md](autotune.md)).

**Режим (переключатель):**

| Режим | Смысл |
|--------|--------|
| **Только Angle PID** | Обход только внутреннего контура; прошивка может работать в режиме «только угол» (`a,2`), см. прошивку. |
| **Только Speed PID** | Подбор внешнего контура; используются команды `f2,...`, каскад **a,1**. |
| **Оба подряд (Angle → Speed)** | Сначала завершается фаза Angle, затем без ручного старта начинается фаза Speed. |

**Поля:**

- Для **Angle** — диапазон **Kp** (начало, конец, шаг). **Ki, Kd, limit** берутся из текущих полей Angle PID на главной вкладке.
- Для **Speed** — отдельный диапазон **Kp**. **Ki, Kd, limit** для Speed — из полей Speed PID на главной вкладке.
- **Сек/шаг** и **max×** — общие для выбранного режима.

**Важно:** для работы автотюна по машинным данным на роботе должна быть включена телеметрия **`x,1`** (см. ниже). Иначе ПК не получит строки `TLM,...` для подсчёта осцилляций.

Кнопки:

- **Старт sweep** — начать выбранный режим.
- **Стоп** — остановить сценарий (на робот снимается режим автотюна / телеметрия — по логике прошивки и модуля автотюна).
- **Продолжить после падения** — после того как робот упал и вы поставили его вертикально: продолжить согласованно с прошивкой (`r`, повтор режима `a,...`, `x,1`).

Если робот **упал** во время серии, автотюн переходит в паузу; не держите робота в воздухе долго — дождитесь статуса восстановления и используйте «Продолжить».

### 3.3. «Графики PID»

Строятся **два графика**: верхний — **Angle PID** (ошибка угла и вклады P, I, D), нижний — **Speed PID**. Данные берутся только из строк **`TLM,...`** при включённой телеметрии **`x,1`**.

- Кнопка **«Очистить графики»** обнуляет буфер точек.
- Если matplotlib не установлен, вкладка покажет подсказку по установке.

### 3.4. «Данные робота»

- Последний **STATUS** (опрос `?` или поток с робота): **fall**, **hz**, режим автотюна **atz**.
- Последняя строка **TLM** в развёрнутом виде.
- Сводка коэффициентов из полей приложения.

Полезно держать эту вкладку открытой при автотюне и отладке.

### 3.5. Консоль Serial

Внизу окна — полный лог исходящих и входящих строк. По нему видно, что именно ушло на Arduino (`>>>`) и что пришло (`<<<`), кроме потоковых данных графика в старом бинарном формате.

## 4. Телеметрия и автотюн на прошивке

Кратко (полный формат — [commands.md](commands.md)):

| Команда | Назначение |
|---------|------------|
| `x,1` | Включить поток `TLM,...` (нужен для автотюна и вкладки графиков). |
| `x,0` | Выключить поток. |
| `a,0` / `a,1` / `a,2` | Режим автотюна: выкл; каскад; только внутренний контур для фазы угла. |

При падении при активном `x,1` возможен маркер **`TLM_FALL`** — приложение использует его для паузы автотюна.

## 5. Типичный порядок работы

1. Подключить COM, при необходимости выполнить калибровку IMU на роботе (`c` или процедура из [calibration.md](calibration.md)).
2. Включить **`x,1`** (можно через отправку команды с ПК, если в интерфейсе есть поле консоли / кнопка — иначе через Serial Monitor один раз).
3. На вкладке PID выставить разумные стартовые Ki, Kd, limit; Kp будет менять автотюн.
4. На вкладке «Автокалибровка» выбрать режим (часто сначала **только Angle**, затем отдельно или **оба подряд** для полного каскада).
5. Наблюдать «Данные робота» и консоль; при падении — поставить робота и **«Продолжить после падения»**.
6. По окончании — **вручную** сохранить понравившиеся коэффициенты в EEPROM (**«Сохранить Angle PID»** / **«Сохранить Speed PID»** или команды `w` / `w2`).

Автотюн **не** пишет EEPROM сам — это сделано намеренно.

## 6. Связка с VR teleop (если используете отдельное приложение)

Если вы параллельно используете среду **vr-teleop** (или аналог) для управления роботом в VR:

- Запускайте клиент VR по инструкции к тому приложению; убедитесь, что **не заняты два разных процесса одним COM-портом** одновременно — Serial доступен только одной программе.
- Калибровку угла нуля и IMU лучше выполнять в спокойном режиме без VR, затем подключать PID Tuner или VR по очереди.
- Сохраните в своём чек-листе назначение клавиш (например, подтверждение калибровки клавишей **Y**), если так задано в vr-teleop — в прошивке Giro-Robot это отдельно от `pid_tuner`.

## 7. Частые проблемы

| Симптом | Что проверить |
|---------|----------------|
| Нет графиков на вкладке PID | Включён ли `x,1`; установлен ли matplotlib. |
| Автотюн «не видит» робота | Порт открыт только здесь; прошивка та же; в логе есть `TLM,...`. |
| После падения странное поведение | Нажать «Продолжить после падения»; проверить `STATUS fall=0`; см. [safety.md](safety.md). |
| Ошибки при запуске Python | `pip install -r requirements.txt`, версия Python ≥ 3.8. |

Больше симптомов — [troubleshooting.md](troubleshooting.md).
